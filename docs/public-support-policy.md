# Public Support Policy

This document defines how public Rove support should be handled in GitHub.

## Purpose

The public support repository exists to collect issues, questions, feature requests, and documentation feedback that can safely be discussed in public.

## Public-safe support

Public GitHub issues are suitable for:

- General bug reports
- Feature requests
- Documentation feedback
- Public questions that may help other users
- Reproducible behavior reports with private details removed

## Private support boundary

Public GitHub issues are not suitable for:

- Account deletion requests
- Billing or entitlement problems
- Purchase restoration problems
- Sensitive diagnostics
- Security reports
- Private account data
- Private infrastructure details

Those requests should be routed to Jarsoft's private support channel once published.

## Diagnostic handling

Users should not be asked to post raw logs publicly by default.

When diagnostic detail is needed publicly, prefer:

- Minimal reproduction steps
- App version and platform
- A short description of expected and actual behavior
- Redacted screenshots
- Small redacted excerpts only when safe

## Triage labels

Recommended labels:

- `type: bug`
- `type: feature`
- `type: docs`
- `type: question`
- `status: needs-triage`
- `status: accepted`
- `status: duplicate`
- `status: cannot-reproduce`
- `status: not-planned`
- `priority: low`
- `priority: normal`
- `priority: high`
- `platform: android`
- `platform: linux`
- `platform: backend`

## Operating principle

Keep public support useful, searchable, and safe. Move private, sensitive, or security-sensitive reports out of public GitHub before details are shared.
