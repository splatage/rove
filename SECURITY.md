# Security Policy

## Reporting security issues

Please do not report security vulnerabilities through public GitHub issues, discussions, pull requests, screenshots, or attachments.

Security reports may contain sensitive information. They should be sent through Jarsoft's private support or security contact channel once published.

Until that channel is published, open a public issue only to ask for the private reporting route. Do not include vulnerability details in that public issue.

## Public issue boundary

Public GitHub issues are appropriate for ordinary bugs, documentation problems, support questions, and feature requests that do not contain sensitive information.

They are not appropriate for reports involving private account data, credentials, sensitive diagnostics, private infrastructure details, billing details, entitlement identifiers, or exploit details.

## Rove security principles

Rove should remain explicit and conservative:

- Commands are never executed silently.
- Configuration is not silently mutated.
- Secrets are not harvested automatically.
- Logs and diagnostics should be shared only by explicit user action.
- Public support and private support remain separate.
